# Виртуальные экскурсии для музеев — ООП-реализация (КТ3)

Объектно-ориентированная версия программы проверки тура перед публикацией.
Реализована на Java, без веб-интерфейса и базы данных (это КТ3; БД появится на КТ4).
Программа запускается из командной строки, прогоняет три проверки на
встроенном демо-туре и выводит результат.

## Требования

- **JDK 21** (LTS) — проверено на OpenJDK 21.0.13 и Temurin 21.0.5.
  Подходит любой совместимый дистрибутив: Oracle JDK, OpenJDK, Temurin, Zulu.
  Важно: нужен именно **JDK** (с компилятором `javac`), а не только JRE.
- Дополнительных библиотек не требуется: используются только стандартные
  классы Java (`java.util`).

## Сборка

Из каталога `src/java/` (там, где лежит этот README и папка `tours/`).

### Linux / macOS

```bash
mkdir -p out
javac -d out $(find java.tours -name "*.java")
```

### Windows — командная строка (cmd)

Команда `find` и подстановка `$(...)` в cmd не работают, поэтому файлы
перечисляются явно через `dir /s /b`. `out` создаётся заранее через `mkdir`:

```bat
mkdir out
for /f "delims=" %f in ('dir /s /b java.tours\*.java') do javac -d out "%f"
```

Если собирать из `.bat`-файла, `%f` нужно удвоить: `%%f`.

Можно и просто перечислить все 16 файлов вручную (работает в любой
версии Windows, без циклов):

```bat
mkdir out
javac -d out java.tours\DemoTour.java java.tours\Exhibit.java java.tours\ExhibitMedia.java java.tours\ExhibitPoint.java java.tours\GraphConnectivityValidator.java java.tours\Hall.java java.tours\HotspotLinksValidator.java java.tours\Main.java java.tours\MediaFile.java java.tours\MediaType.java java.tours\PanoramaFormatValidator.java java.tours\Point.java java.tours\Tour.java java.tours\TourStatus.java java.tours\TourValidator.java java.tours\TransitionPoint.java
```

### Windows — PowerShell

```powershell
New-Item -ItemType Directory -Force -Path out | Out-Null
javac -d out (Get-ChildItem -Path java.tours -Recurse -Filter *.java)
```

Скомпилированные `.class`-файлы попадут в `out/`. Эта папка исключена
из репозитория через `.gitignore`.


## Запуск

Программа использует встроенные демо-туры — никаких внешних файлов не нужно.
За один запуск прогоняются оба тура: сначала корректный, затем тур с ошибками
всех типов. Аргументы командной строки не требуются.

```bash
java -cp out java.tours.Main
```

Ожидаемый вывод:

```
========== Демо-тур 1: корректный тур ==========
Тур: Виртуальная экскурсия: Краеведческий музей (залов: 3, экспонатов: 1)

Ошибок не найдено. Тур корректен.
Опубликовано по ссылке: https://java.tours.example.ru/t/1
Статус: PUBLISHED

========== Демо-тур 2: тур с ошибками всех типов ==========
Тур: Тестовый тур с ошибками всех типов (залов: 5, экспонатов: 0)

Найдено ошибок: 9
  - Ошибка: Панорама зала 301 имеет недопустимое расширение (.gif)
  - Ошибка: Панорама зала 302 имеет неверное соотношение сторон (1000x1000)
  - Ошибка: Точка 13 ведёт в тот же зал 303
  - Ошибка: Точка 14 ведёт в несуществующий зал 999
  - Ошибка: Зал 305 является тупиком (нет исходящих переходов)
  - Ошибка: Из зала 302 нельзя попасть во все остальные залы (достигнуто 4 из 5)
  - Ошибка: Из зала 303 нельзя попасть во все остальные залы (достигнуто 3 из 5)
  - Ошибка: Из зала 304 нельзя попасть во все остальные залы (достигнуто 2 из 5)
  - Ошибка: Из зала 305 нельзя попасть во все остальные залы (достигнуто 1 из 5)
Публикация отменена: тур содержит ошибки.
```

Первый демо-тур корректен — валидаторы возвращают пустой список, экскурсия
публикуется. Это гарантирует, что валидаторы не выдают ложных срабатываний
на нормальных данных.

Второй демо-тур устроен так, чтобы покрыть все 5 типов ошибок, которые
умеют ловить валидаторы — по одной основного вида на каждый валидатор.
Распределение ошибок:

**`PanoramaFormatValidator`** (операция №1 «Проверить формат панорам»):

1. Зал 301 — недопустимое расширение `.gif` (допустимы `.jpg`, `.jpeg`, `.png`).
2. Зал 302 — неверное соотношение сторон `1000×1000` (1:1 вместо требуемого 2:1).

**`HotspotLinksValidator`** (алгоритм №1 «Проверить связи точек перехода»):

3. Точка 13 в зале 303 — петля: ведёт в тот же зал 303, где находится сама.
4. Точка 14 в зале 304 — битая ссылка: ведёт в несуществующий зал 999.

**`GraphConnectivityValidator`** (алгоритм №2 «Проверить связность графа тура»):

5. Зал 305 — тупик: нет ни одной исходящей точки перехода.
6–9. Нарушения связности в залах 302, 303, 304, 305. Это следствие
   однонаправленной цепи `301 → 302 → 303 → 304 → 305` без обратных рёбер:
   из каждого зала, кроме 301, нельзя вернуться к предыдущим. Зал 301
   в ошибки не попадает, потому что из него по цепи достижимы все пять.

Граф переходов во втором демо-туре:

```
   301 ──→ 302 ──→ 303 ──→ 304 ──→ 305   (305: тупик, нет исходящих)
              ↺ 303          ↓
                          (битая) → 999
```

> **⚠ Важно: имя класса — `java.tours`, без префикса `java.`**
>
> Пакет называется `tours` (без `java.`). Полное имя главного класса —
> `java.tours`. Если случайно написать `java.tours.Main` (по аналогии
> со встроенными пакетами `java.util`, `java.lang`), JVM выдаст ошибку:
>
> ```
> Error: A JNI error has occurred, please check your installation and try again
> Exception in thread "main" java.lang.SecurityException:
>   Prohibited package name: java.java.tours
> ```
>
> Причина: пакеты, начинающиеся с `java.`, зарезервированы самой JVM,
> использовать их в прикладном коде запрещено. Решение — убрать `java.`
> из команды запуска.

## Структура классов

Исходники лежат в одном плоском пакете `tours` — без вложенностей и
внешних зависимостей. 16 файлов:

| Файл | Роль | Соответствие КТ2 |
|---|---|---|
| `TourStatus.java` | enum: DRAFT / READY / PUBLISHED | атрибут «Статус» сущности «Экскурсия» |
| `MediaType.java` | enum: AUDIO / PHOTO / TEXT / MODEL_3D | атрибут «Тип» сущности «Медиафайл» |
| `MediaFile.java` | класс-сущность | сущность «Медиафайл» |
| `ExhibitMedia.java` | ассоциативный класс | связь M:N «Экспонат-Медиа» |
| `Exhibit.java` | класс-сущность | сущность «Экспонат» |
| `Point.java` | абстрактный базовый класс | обобщение «Точка перехода» и «Точка экспоната» |
| `TransitionPoint.java` | наследник `Point` | сущность «Точка перехода» |
| `ExhibitPoint.java` | наследник `Point` | сущность «Точка экспоната» |
| `Hall.java` | класс-сущность | сущность «Зал» |
| `Tour.java` | корневой агрегат | сущность «Экскурсия» |
| `TourValidator.java` | интерфейс | контракт проверки тура |
| `PanoramaFormatValidator.java` | реализация интерфейса | операция №1 «Проверить формат панорам» |
| `HotspotLinksValidator.java` | реализация интерфейса | алгоритм №1 «Проверить связи точек перехода» |
| `GraphConnectivityValidator.java` | реализация интерфейса | алгоритм №2 «Проверить связность графа тура» |
| `DemoTour.java` | фабрика демо-туров | технический класс |
| `Main.java` | точка входа (CLI) | технический класс |

## Сопоставление с процедурной версией

Процедурная версия (КТ2) написана на Python 3.13 и состоит из функций
`validate_panorama_format()`, `check_hotspot_links()`,
`check_graph_connectivity()`. ООП-версия реализует те же операции как
классы-реализации интерфейса `TourValidator`:

| Процедурная (Python)              | ООП (Java)                       |
|-----------------------------------|----------------------------------|
| `validate_panorama_format()`      | `PanoramaFormatValidator`        |
| `check_hotspot_links()`           | `HotspotLinksValidator`          |
| `check_graph_connectivity()`      | `GraphConnectivityValidator`     |

На одних и тех же входных данных (демо-тур) обе версии возвращают
пустой список ошибок — результаты совпадают.

## Тесты

Отдельных модульных тестов в архиве нет: проверка корректности
выполняется одним запуском `java -cp out tours.Main`, который прогоняет
оба демо-тура подряд:

- демо-тур 1 (корректный) — ожидается «Ошибок не найдено», публикация
  выполнена;
- демо-тур 2 (с ошибками) — ожидается 9 ошибок, по одной каждого из
  5 типов, которые умеют ловить валидаторы (расширение, пропорции,
  петля, битая ссылка, тупик; нарушения связности — как следствие
  однонаправленной цепи и тупика). Публикация отменена.
